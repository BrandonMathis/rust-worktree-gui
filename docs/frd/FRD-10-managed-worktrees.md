# FRD-10 — Managed worktrees

**Goal:** A worktree can be run by a coding agent (Claude Code, Codex or Pi) through a small built-in harness UI, instead of a terminal.

**Source:** request (2026-11-24): *"Create the ability to create a "managed" work tree. This is not alacrity but a custom ui that I select to prompt in claude, codex, or Pi. The ui is a simplistic coding agent harness. Thinking and tool calls are shown as summary collapsed similar to claude with brief descriptions of their activity instead of the whole verbose tool call. Upon creating a managed tree, you are presented with an input field in the center of the working panel where alacrity would go. In that panel you can pick harness (name and icon in list), model (of the selected harnesses provided models), thinking level and then submit the prompt. Follow up messages are permitted and are always queued to go in after the harnesses turn is complete."*

## Out of scope

- Saving the displayed conversation across restarts. The harness keeps the session (follow-ups continue it), but the app's transcript starts empty after a restart.
- Converting an existing terminal worktree to a managed one, or back.
- Streaming reply text token by token; replies appear when each message completes.
- Answering permission prompts interactively, images and attachments, and markdown rendering of replies.
