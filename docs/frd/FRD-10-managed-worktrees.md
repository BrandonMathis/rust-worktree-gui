# FRD-10 — Managed worktrees

**Goal:** A worktree can be handed to a coding agent. Instead of a terminal, its pane is a small agent harness: pick Claude, Codex or Pi, a model and a thinking level, and prompt it.

**Source:** 2026-11-24: *"Create the ability to create a 'managed' work tree. This is not alacrity but a custom ui that I select to prompt in claude, codex, or Pi. The ui is a simplistic coding agent harness. Thinking and tool calls are shown as summary collapsed similar to caldue with brief descriptions of their activity instead of the whole verbose tool call. Upon creating a managed tree, you are presented with an input field in the center of the working panel where alacrity would go. In that panel you can pick harness (name and icon in list), model (of the selected harnesses provided models), thinking level and then submit the prompt. Follow up messages are permitted and are always queued to go in after the harnesses turn is complete. Use proper sdks for each harness for interacting with them in this programmatic way."*

## Out of scope

- **Conversations across restarts.** A conversation lives as long as the app runs. The harnesses keep their own session files, but the app doesn't resume them yet.
- **Approving tool calls in the app.** See MGD-12. Until there is an approval prompt, choose a Claude permission mode that doesn't need one.
- **Changing the harness, model or thinking level mid-conversation.** Start a **New Chat** instead.
- **Attachments.** Prompts are text; dropped files aren't pasted into the prompt field.
