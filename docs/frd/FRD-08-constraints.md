# FRD-08 — Constraints and non-functional requirements

**Source:** initial request (2026-11-20T21:47Z): *"we're going to build in Rust… We are running on macOS… I specifically want to use Rust. I want to use Rust common conventions."* Project goals: (1) a small running Rust prototype, (2) learn Rust UI development coming from React.

| ID | Priority | Requirement | Verification | Status |
| --- | --- | --- | --- | --- |
| NFR-01 | Must | A standalone Rust application (edition 2024, Rust 1.90 pinned in `.tool-versions`) using iced 0.14 with the Elm-style `State → Message → update → view` architecture. It isn't a plugin to Pi or Alacritty. | Build: `cargo build --locked` | Implemented |
| NFR-02 | Must | Targets macOS. Required external tools: Git ≥ 2.41 and tmux ≥ 3.5. Optional: `gh` (PR badge) and VS Code (Open in VS Code). | Manual | Implemented |
| NFR-03 | Must | Subprocesses use argument vectors, never shell-built strings. Paths are kept as `PathBuf`/bytes end to end. | `preserves_paths_and_parses_flags`, `isolates_sessions_without_overriding_home_config_and_passes_a_literal_cwd` | Implemented |
| NFR-04 | Must | Git, tmux, `gh` and `open` run off the UI thread and return typed results as messages. | `switching_worktrees_ignores_a_stale_connection_result`, `stale_refresh_results_are_ignored_after_replacing_the_anchor`, `pr_badge_belongs_to_the_selected_worktree_only` | Implemented |
| NFR-05 | Must | The app never modifies Git state (no add, remove or prune), user configs, or tmux sessions other than its own name migration. It creates sessions for worktrees (`new-session`) and moves its own terminal's client between them (`switch-client`), but never kills a session or changes its options. | `deduplicates_linked_checkouts_and_persists_anchor_replacement` (forget leaves Git intact); Manual (code review) | Implemented |
| NFR-06 | Must | Only HTTPS URLs are passed to the OS opener. | `rejects_unsafe_or_mismatched_pull_request_urls` | Implemented |
| NFR-07 | Must | `cargo fmt --all --check`, `cargo clippy --all-targets -D warnings` and `cargo test` pass for the app and the vendored `iced_term` (a workspace member). | CI command set in [README](README.md#how-to-verify) | Implemented |
| NFR-08 | Should | Typing and scrolling in the embedded terminal feel as immediate as standalone Alacritty. The draw loop does no per-cell parsing (palette colors are resolved once per theme), ASCII cells use basic text shaping, a burst of PTY output costs one grid sync instead of one per wakeup, and the PTY is resized only when the font changes. Dependencies are optimized in dev builds. | `named_colors_resolve_from_the_palette_without_reparsing`, `extended_indexed_colors_use_the_xterm_cube_and_gray_ramp`, `shapes_ascii_cells_basically_and_falls_back_for_other_glyphs`, `bursts_of_wakeups_become_one_redraw_after_other_events` (vendored `iced_term` tests; `cargo test --locked` and CI run them as part of the workspace); Manual: hold a key and trackpad-scroll a long `git log` in `cargo run --locked`, and confirm there is no visible lag versus Alacritty | Implemented |
| NFR-09 | Must | Dependency supply chain: Dependabot opens version-update PRs for minor and major releases only, after a 14-day cooldown (30 days for majors). Patch releases arrive only as security updates for a published advisory. CI builds with `--locked`, actions are pinned to commit SHAs, `cargo deny` gates every PR and runs daily, and a weekly report flags direct dependencies that are two or more breaking releases behind (or one behind for 180+ days), yanked, or without a release for 3 years, plus a toolchain 4+ releases behind stable. Policy: [SECURITY.md](../../SECURITY.md). | `cargo deny check`; report rules: `ruby scripts/test/dependency_health_test.rb` (`test_pre_1_0_minor_releases_count_as_breaking_lines`, `test_one_breaking_release_behind_is_flagged_only_after_the_grace_period`, `test_a_yanked_locked_version_is_flagged`, `test_years_without_a_release_is_flagged_but_a_quiet_stable_crate_is_not`, `test_toolchain_is_flagged_once_it_falls_the_limit_behind_stable`); Manual: confirm Dependabot alerts and security updates are on in the repository settings | Implemented |
