# FRD-08 — Constraints and non-functional requirements

**Source:** initial request (2026-11-20T21:47Z): *"we're going to build in Rust… We are running on macOS… I specifically want to use Rust. I want to use Rust common conventions."* Project goals: (1) a small running Rust prototype, (2) learn Rust UI development coming from React.

| ID | Priority | Requirement | Verification | Status |
| --- | --- | --- | --- | --- |
| NFR-01 | Must | A standalone Rust application (edition 2024, Rust 1.90 pinned in `.tool-versions`) using iced 0.14 with the Elm-style `State → Message → update → view` architecture. It isn't a plugin to Pi or Alacritty. | Build: `cargo build --locked` | Implemented |
| NFR-02 | Must | Targets macOS. Required external tools: Git ≥ 2.41 and tmux ≥ 3.5. Optional: `gh` (PR badge) and VS Code (Open in VS Code). | Manual | Implemented |
| NFR-03 | Must | Subprocesses use argument vectors, never shell-built strings. Paths are kept as `PathBuf`/bytes end to end. | `preserves_paths_and_parses_flags`, `isolates_sessions_without_overriding_home_config_and_passes_a_literal_cwd` | Implemented |
| NFR-04 | Must | Git, tmux, `gh` and `open` run off the UI thread and return typed results as messages. | `switching_worktrees_ignores_a_stale_connection_result`, `stale_refresh_results_are_ignored_after_replacing_the_anchor`, `pr_badge_belongs_to_the_selected_worktree_only` | Implemented |
| NFR-05 | Must | The app never modifies Git state (no add, remove or prune), user configs, or tmux sessions other than its own name migration. It creates sessions for worktrees (`new-session`) and moves its own terminal's client between them (`switch-client`), but never kills a session or changes its options. | `confirming_removal_only_unbookmarks_the_project_and_detaches_its_terminal` (removing a bookmark leaves Git intact); Manual (code review) | Implemented |
| NFR-06 | Must | Only HTTPS URLs are passed to the OS opener. | `rejects_unsafe_or_mismatched_pull_request_urls` | Implemented |
| NFR-07 | Must | `cargo fmt --all --check`, `cargo clippy --all-targets -D warnings` and `cargo test` pass for the app and the vendored `iced_term` (a workspace member). | CI command set in [ci.yml](../../.github/workflows/ci.yml) | Implemented |
| NFR-08 | Should | Typing and scrolling in the embedded terminal feel as immediate as standalone Alacritty. The draw loop does no per-cell parsing (palette colors are resolved once per theme), ASCII cells use basic text shaping, a burst of PTY output costs one grid sync instead of one per wakeup, and the PTY is resized only when the font changes. Dependencies are optimized in dev builds. | `named_colors_resolve_from_the_palette_without_reparsing`, `extended_indexed_colors_use_the_xterm_cube_and_gray_ramp`, `shapes_ascii_cells_basically_and_falls_back_for_other_glyphs`, `bursts_of_wakeups_become_one_redraw_after_other_events` (vendored `iced_term` tests; `cargo test --locked` and CI run them as part of the workspace); Manual: hold a key and trackpad-scroll a long `git log` in `cargo run --locked`, and confirm there is no visible lag versus Alacritty | Implemented |
| NFR-09 | Must | Dependency supply chain: Dependabot opens version-update PRs for minor and major releases only, after a 14-day cooldown (30 days for majors). Patch releases arrive only as security updates for a published advisory. CI builds with `--locked`, actions are pinned to commit SHAs, `cargo deny` gates every PR and runs daily, and a weekly report flags direct dependencies that are two or more breaking releases behind (or one behind for 180+ days), yanked, or without a release for 3 years, plus a toolchain 4+ releases behind stable. Policy: [SECURITY.md](../../SECURITY.md). | `cargo deny check`; report rules: `ruby scripts/test/dependency_health_test.rb` (`test_pre_1_0_minor_releases_count_as_breaking_lines`, `test_one_breaking_release_behind_is_flagged_only_after_the_grace_period`, `test_a_yanked_locked_version_is_flagged`, `test_years_without_a_release_is_flagged_but_a_quiet_stable_crate_is_not`, `test_toolchain_is_flagged_once_it_falls_the_limit_behind_stable`); Manual: confirm Dependabot alerts and security updates are on in the repository settings | Implemented |
| NFR-10 | Must | Every subprocess (git, tmux, `gh`, `open`) goes through one runner (`src/runner.rs`). It finds tools on `PATH`, then in `/opt/homebrew/bin`, `/usr/local/bin`, `/opt/local/bin` and `/usr/bin` (`WORKTREE_BROWSER_TMUX` overrides tmux). It removes the Git variables that redirect repository discovery (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_NAMESPACE`, `GIT_CEILING_DIRECTORIES`, `GIT_DISCOVERY_ACROSS_FILESYSTEM`, `GIT_PREFIX` and the rest of Git's `local_repo_env`, listed in `runner::GIT_OVERRIDES`), closes stdin, and kills a tool that outlives its timeout (git queries 30 s, `init`/`worktree add` 5 min, tmux queries 5 s, `open` 15 s, `gh` 8 s). A timeout is a readable error, so a hung git can't leave **Refresh** disabled. The same variables are removed from the app's own environment at startup, so shells in the embedded terminal don't inherit them. | `subprocesses_never_inherit_git_repository_overrides`, `a_hung_tool_is_stopped_at_its_timeout_with_a_readable_error`, `a_hung_git_fails_with_a_readable_error_instead_of_blocking`, `refresh_is_usable_again_after_git_times_out`, `tools_are_found_on_path_then_in_homebrew_folders_and_tmux_can_be_overridden`; Manual: from a shell with `GIT_DIR=/tmp/elsewhere` exported, run `cargo run --locked` while no `worktree-browser` tmux server is running, open a worktree and confirm `echo $GIT_DIR` prints nothing and `git status` shows that worktree | Implemented |
| NFR-11 | Should | Keystroke-to-pixels latency of typing into the embedded terminal is measured on every pull request that changes the app (`src/`, `vendor/`, Cargo files, the harness), and the check fails when the PR makes it worse. A harness built into the app (`cargo build --features perf`, `src/perf/`; off in normal builds) drives the real app headlessly: it presses keys through iced's widget tree as macOS delivers them and times each one until the rendered frame's pixels change. Scenarios, all keys typed into the embedded terminal: typing, Backspace, moving the cursor left/right and up/down, Return scrolling the screen, Page Down repainting it. CI measures typing (`type_character`); the others run locally with `--only`. The terminal runs a deterministic line editor instead of tmux, so only the app's pipeline is measured. Frames are drawn with wgpu (tiny-skia without a GPU), at user-interactive QoS like a UI thread. `scripts/latency.rb` builds base and head in release mode and runs them in turns per scenario on one machine; key → pixels and the app's own work (update + view + draw) fail when head is slower by more than 15% or 3σ of base's spread (1.4826 × MAD), and the slowdown is real: Mann–Whitney p < 0.01, slower in every round, above a noise floor (0.5 ms / 0.05 ms). `.github/workflows/latency.yml` runs it on those PRs and puts the report in the job summary. | `every_measured_terminal_key_changes_the_screen`, `typed_characters_echo_and_insert_at_the_cursor`, `cursor_keys_move_only_within_the_line_and_the_screen`, `escape_sequences_split_across_reads_are_decoded_once_complete`, `reset_reads_the_size_and_puts_the_prompt_on_the_bottom_row`, `a_full_line_starts_over_instead_of_wrapping` (`cargo test --locked --features perf perf::`); rules: `ruby scripts/test/latency_test.rb` (`test_a_slowdown_beyond_the_percentage_budget_fails`, `test_a_shift_beyond_the_sigma_budget_fails_even_under_the_percentage_budget`, `test_the_app_work_metric_is_gated_too`, `test_run_to_run_noise_passes`, `test_one_stalled_round_does_not_move_the_result`, `test_a_slowdown_in_only_some_rounds_is_a_warning_not_a_failure`, `test_a_slowdown_below_the_absolute_floor_never_fails`, `test_phase_metrics_are_reported_but_never_fail`, `test_runs_with_different_renderers_are_not_compared`); Manual: `ruby scripts/latency.rb` passes when base and head are the same commit, and fails after drawing every terminal glyph twice in `vendor/iced_term/src/view.rs` | Implemented |
