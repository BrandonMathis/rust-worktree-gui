# FRD-06 — Pull request detection

**Source:** 2026-11-20T23:05Z: *"attempt to detect if there is PR open for this worktree. If so have icon next to dropleft in upper right that is PR icon with Worktree # and number that when you click opens worktree in os default browser"*. Confirmed at 23:39Z that only **open** PRs show a badge (merged PRs don't).

| ID | Priority | Requirement | Verification | Status |
| --- | --- | --- | --- | --- |
| PR-01 | Must | When a project's inventory loads (startup, **Refresh**, after creating a worktree), or a different worktree on a branch is selected, the app runs **one** `gh pr list --state all --limit 200 --json number,state,isDraft,headRefName,url,isCrossRepository` from the project's anchor checkout, using the user's existing `gh` login. At most one lookup per project runs at a time; its answer is matched against the worktrees listed when it arrives. | `lists_pull_requests_once_from_the_project_checkout_without_prompting`, `selecting_a_worktree_connects_its_terminal_and_looks_up_its_pr`, `refresh_keeps_pr_badges_until_the_new_lookup_answers` | Implemented |
| PR-02 | Must | Each worktree is matched to a PR whose head branch equals its branch. PRs from forks (`isCrossRepository`) are ignored, because a fork can reuse any branch name. If several PRs share the branch, an open or draft PR wins over a closed or merged one, and within that group the highest number (the most recently created) wins. The badge shows the PR number and its state (open, draft, closed or merged). Branches whose only PR is older than the 200 most recent show no badge. | `detects_each_pull_request_status_for_the_matching_branch`, `several_pull_requests_for_one_branch_prefer_open_then_most_recent` | Implemented |
| PR-03 | Must | Clicking the badge opens the PR URL in the default browser. Only `https://…/pull/<N>` URLs are accepted; other schemes, credentials in the host, whitespace or a mismatched number drop that PR. | `detects_each_pull_request_status_for_the_matching_branch`, `rejects_unsafe_or_mismatched_pull_request_urls` | Implemented |
| PR-04 | Must | The lookup never prompts (`GH_PROMPT_DISABLED`, `GIT_TERMINAL_PROMPT=0`, no stdin), ignores `GH_REPO`, and is stopped after 8 seconds. A missing or logged-out `gh`, an error, or a timeout hides the project's badges silently. | `lists_pull_requests_once_from_the_project_checkout_without_prompting`, `a_failing_gh_hides_the_badge`, `a_slow_gh_times_out_and_hides_the_badge`, `pr_badges_are_kept_for_unselected_worktrees_and_ignore_stale_results` | Implemented |
| PR-05 | Must | The header badge shows the selected worktree's PR; the sidebar keeps every worktree's PR icon. A refresh keeps existing badges until the new lookup answers (no flicker), but drops a badge at once if its worktree disappeared or changed branch. Answers to an older lookup, or one from before **Replace Anchor**, are ignored. Clicking the already-selected worktree doesn't run `gh` again. | `refresh_keeps_pr_badges_until_the_new_lookup_answers`, `pr_badges_are_kept_for_unselected_worktrees_and_ignore_stale_results`, `clicking_the_selected_worktree_again_does_not_look_up_its_pr_again`, `forgetting_the_selected_project_detaches_and_selects_the_next` | Implemented |
| PR-06 | Must | Detached HEAD and unavailable worktrees never get a badge, and selecting one doesn't start a lookup. | `selecting_a_worktree_connects_its_terminal_and_looks_up_its_pr`, `unavailable_worktrees_never_start_a_terminal` | Implemented |
